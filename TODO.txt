- [FIXED] Garmin export: total distance reported is inflated.
   - Root cause: Garmin's JSON upload pipeline silently strips the
     top-level `estimateType` and `estimatedDurationInSecs` fields,
     then recomputes the displayed total from the step structure and
     incorrectly sums each lap.button rest's `endConditionValue` into
     the total. Confirmed by re-uploading a Garmin-UI-created baseline
     workout (Baseline.json): 1100yd -> 1500yd (+400 = 2 lap.button
     rests * 200). Same math holds for our workouts (4 * 200 = +800).
   - Workaround in src/garminExport.ts: emit `endConditionValue: 0`
     for lap.button rests instead of the canonical 200. Field is
     meaningless for lap.button (rest ends on button press), so 0 is
     functionally fine and short-circuits Garmin's buggy recompute.
   - Editing-and-saving the workout in Garmin's web UI also fixes
     the displayed total (it re-sets estimateType), but we can't
     ask users to do that for every upload.
   - Should still be filed with Garmin as an upstream bug.

- Garmin-side bug (unit handling on round-trip) — NOT fixable from our
  code, file as a complaint to Garmin:
   - Workout X is really 2500 yd.
   - Original (sourced from MySwimPro) on Garmin Connect: website shows
     2286 yd; watch shows 2500 yd correctly.
   - After downloading from Garmin Connect and re-uploading the same
     file: website shows 2500 yd; watch now shows 2734 yd.
   - Diffed before (old.json) vs. after (new.json). Per-step distances
     are byte-identical. Only meaningful payload change:
       estimatedDistanceInMeters: 2286 -> 2500
     i.e. Garmin converted m -> yd (2286 * 1.0936 = 2500) and wrote the
     yd value back into the meters-named field on re-upload. The watch
     then reads it as meters again -> 2500 m -> 2734 yd display.
   - Side observations during the round-trip (also Garmin's doing):
       * consumer / consumerName / workoutProvider get nulled out.
       * Description em-dashes get mojibaked (UTF-8 reinterpreted as
         Latin-1: "—" -> "â").
       * stepIds get reassigned.
   - Our code is not in the loop for this round-trip; do NOT try to
     "fix" it in garminExport.ts.

  Worth testing whether switching to actual meters makes our originated
